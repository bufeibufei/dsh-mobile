# B0 手机设置入口 v1

手机界面保持 DSH 官方会话、预设、轨迹、用量及认证协议。本合同只约定固定 DSH Host 网页与 Android 壳之间的三种设置导航事件；不新增 HTTP/WS 路由或数据字段。

## Host → Android

固定 DSH Client 移动扩展在设置根页提供三个 Jarvis 行。只有用户明确点击对应行时，顶层页面才调用 `window.JarvisB0Settings.postMessage(value)`：

| `value`（严格字符串） | 页面动作 |
| --- | --- |
| `account` | 打开原生“账号与安全”单列页 |
| `servers` | 打开原生“服务器”单列页 |
| `connection` | 打开原生“连接状态与文件”单列页 |

不发送 Cookie、账号、密码、服务器地址、文件内容或其它负载；不提供网页到原生的任意命令/数据通道，也不依赖异步回复。缺少安全 WebMessage listener 时，网页显示可见的不可用提示，不静默吞掉点击，也不退化为全局 `addJavascriptInterface`。

Android 使用 AndroidX WebKit `addWebMessageListener`，只允许当前选中的**精确 origin**。接受事件时再次检查消息类型为字符串、值恰为上表之一、`isMainFrame`、`sourceOrigin` 与当前选中 origin 相同、当前顶层 URL 属于该 Host，以及改密事务未阻塞。旧页面/旧连接的回调不得打开新服务器的设置。切服、登出及 Activity 销毁时移除旧 listener；新连接在加载网页前绑定新 origin。原生页返回到原 DSH 设置页；切服/登出则关闭旧页并走已有认证流程。

## Android → Host 的返回行为

固定 Host 移动扩展提供 `window.__JARVIS_B0_MOBILE__?.back()` 同步布尔函数。Android 系统返回先关闭当前原生设置页；否则调用该函数，让网页先关闭当前最上层的 DSH 页面或浮层。只有返回 `false` 时才沿用 WebView 历史或退出行为。该函数不发送消息、不触发模型，也不修改会话。

### 手机导航补充

仍使用同一 `back()` 布尔接口，不增加消息值、HTTP/WS 路由或任意网页到原生命令。返回动作按可见层级逐次执行：先关闭确认框、插件操作弹窗等最上层模态内容；DSH 设置详情页返回手机设置根页，设置根页再关闭并回原会话；随后处理覆盖式左侧抽屉或右侧工具分栏，最后在全局“插件”主面板时返回当前 Conversation。Jarvis 原生设置子页先于网页返回关闭，回到其原 DSH 设置层。一次系统返回只处理一个当前层级；没有实际处理才返回 `false`。

固定 DSH `0.2.1-alpha.2` 的“插件”是内部主面板 `plugins`，不创建浏览器历史项。Host 扩展须读取 DSH 当前面板状态，并通过其布局控制器选择 Conversation；插件详情沿用 DSH 自带的返回列表动作。插件主面板增加手机可见返回入口。手机设置根页是同一官方设置模态内容的移动导航层：展示 DSH 设置分组和三个 Jarvis 原生入口；点 DSH 项进入官方内容，不能复制或替代其配置逻辑。设置页及右工具分栏使用对应的原生关闭动作；可见入口与系统返回遵循相同的层级语义。离开这些页面保留原 Session、草稿、Cookie 与插件状态，不刷新 WebView，不以返回触发安装、启停插件或模型调用。

上述事件与已有 `jarvisFileExport` 文件桥彼此独立；文件桥的来源、大小及请求身份规则仍按 [文件导出](file-export.md)。

### 设置层级补充

手机设置根页是唯一的设置分类入口，分为两个平级分组：`DSH` 下为通用、模型、内置插件、Agent 预设，`Jarvis App` 下为账号与安全、服务器、连接状态与文件。后面三个条目继续只发送上表固定的 `account`、`servers`、`connection`，不得把账号、服务器或连接入口再次注入 DSH 通用详情。DSH 条目进入官方设置详情，保留原控件与原配置动作。

进入任一 DSH 详情后，顶部只呈现当前标题和返回设置根页的入口，不再显示全局四分类切换条；详情内部原有且有实际功能的子标签不受此限制。根页有明确的关闭入口回原会话。返回根页时保留根页滚动位置，关闭后再次打开设置从根页开始。Jarvis 原生设置页关闭后回到设置根页。

同一个 `back()` 布尔函数继续逐层处理：可见键盘或顶层模态先退出，随后是 DSH 详情到根页、根页到原会话；Android 原生页先由 Android 自行关闭回根页。可见返回按钮和系统返回手势应得到相同结果，每次仅处理一层。不得刷新 WebView、改变 Session/草稿/Cookie、增加桥消息值或新增 HTTP/WS 路由。

### 设置首页精简补充

手机设置根页的**显示顺序和分组标题**改为 `Jarvis` 在前、`DSH` 在后，替代上一节的 `DSH` / `Jarvis App` 顺序与标题；七个入口和功能不变。`Jarvis` 组依次显示“服务器”“连接状态与文件”“账号与安全”，仍分别发送 `servers`、`connection`、`account`。缺少安全 Android listener 时，在 Jarvis 组内、靠近所点击入口显示可见提示，不因提示滚动到 DSH 组底部。根页只显示关闭操作。

`DSH` 组依次显示“通用”“模型”“内置插件”“Agent 预设”。移动扩展须先核对固定 DSH `0.2.1-alpha.2` 的四个官方分类名称与顺序，再把中文入口映射到对应官方详情；核对失败时保留官方设置导航，不猜测错位映射。详情继续使用官方配置控件，顶栏只显示当前标题与返回；返回根页时恢复原滚动位置，并将焦点交还进入详情时的入口。桌面 DSH 设置导航不随此补充改变。

这次只有 Host 网页的移动呈现变化：不合并或重写三个 Android 原生设置页，不新增桥值、HTTP/WS 路由、认证状态或设置写入逻辑，不刷新会话。浏览器与隔离 DSH 检查不能代替 Android WebView、实体手机或现役 Host 验收。
